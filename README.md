# Open-Q

An open-source JUCE equalizer by **Yohan Senanayake**, developed incrementally as an alternative to FabFilter Pro-Q. Open-Q provides 24 mono/stereo EQ slots supporting Bell, Low Shelf, High Shelf, Low Cut (high pass), and High Cut (low pass) with custom ZLE-derived Ivantsov coefficients, DAW automation, saved state, a combined frequency-response graph, and a pre/post spectrum analyzer.

Click a graph node to open its compact band card. Use the compact type/slope selectors on the left of the card, edit frequency/gain/Q with the knobs beside them, and use the power icon to toggle **On / Bypass**. The power icon is cyan when On and muted when bypassed; the trash icon sets **Off**. Click empty graph space to hide the card without changing audio; the X button also hides the card without changing the band. Click its node to reopen it. The trash button deletes the selected band (sets Off) and selects another band if one remains. The type and slope menus open inside the plugin editor rather than in separate native popup windows; changing bands or hiding the card closes their menus. The card starts hidden and overlays the graph, avoiding the selected node; it stays still while a knob is dragged and retains its current position afterward unless that position obstructs the selected node or no longer fits the usable area. Off marks an unused slot; Bypass keeps an existing band without applying its EQ; On applies its EQ. Band 1 starts On and the others start Off. All statuses retain their settings. Double-click the graph background to create a band in an Off slot. Selection only changes the editing controls: all On bands process audio in slot order, each with independent channel histories.

Each band's frequency ranges from 20 Hz to 20 kHz (capped at 49% of sample rate), gain from -24 to +24 dB, and Q from 0.1 to 10. Shelf frequency is the half-gain midpoint, and shelf Q controls resonance; high Q can exceed the requested gain substantially. Controls smooth over 20 ms; switching between On and either silent status fades over 20 ms. Bypass keeps the filter running internally on its current input, including coefficient updates and smoothing after knob changes, while passing dry audio once the fade completes. Returning to On fades in the continuously updated filter output. Off clears filter history after fading dry and then skips filtering; a flat gain-based On band also clears history once dry. Bypass therefore continues using DSP CPU even though it contributes no EQ to the audible signal. Changing response type or cut slope fades the old filter to dry over 20 ms, resets its history while dry, then fades in the new response over 20 ms. This can briefly reduce the EQ contribution during type automation. Double-click resets a knob. The default flat settings and bank with no On bands pass audio through unchanged. No buffering latency is added. Stacked boosts can produce very large levels; there is no output limiter. A conservative 120-second tail allowance lets hosts render extreme cascaded low-frequency ringing.

Cuts offer **6, 12, 18, 24, 36, 48, 72 and 96 dB/octave** slopes, defaulting to 12. Gain is retained but inactive for cuts; Q is retained but inactive at 6 dB/octave. The disabled slope selector stays visually inactive on hover and skips hover-triggered repaints and click focus; these behaviors return when a cut is selected. Q reset uses the neutral cut value 1/sqrt(2); converting an existing band preserves its stored Q, so the existing Q=1 setting is resonant for a cut. Cuts process normally at zero gain. Cut nodes sit at 0 dB and edit frequency horizontally. Their Q wheel is disabled at 6 dB/octave. The 18 dB/octave design uses a first-order section plus a biquad with internal Q=sqrt(2)*user Q; higher even orders follow ZLE's section-Q distribution. Up to eight fixed sections per channel provide 96 dB/octave. Ivantsov low-pass sections retain finite attenuation at Nyquist; the graph shows that digital behavior.

The graph shows the **combined target digital response** of all bands set to On using the same coefficient-design function as the audio DSP, on a logarithmic frequency axis and a -24 to +24 dB gain axis. Band responses add in dB before the combined display is clipped. A low-priority worker calculates 400 response points; triple buffers hand off geometry and completed drawing frames without making audio processing wait for the UI. The displayed range ends at Nyquist when it is below 20 kHz.

Graph nodes follow each band's own frequency and gain. Shelf nodes sit at half the requested gain, matching the shelf midpoint; dragging still edits the full -24 to +24 dB gain range. Click a node to select it and update the shared controls; drag horizontally for frequency and vertically for gain. Shift-drag gives fine control. Ctrl/Command with left drag locks frequency; with right drag it locks gain. Motion while an axis is locked is consumed so unlocking does not replay it. Wheel over a node edits Q, with Shift for finer changes. Bypassed nodes remain dimmed and editable; Off nodes are hidden. The faint selected-band curve remains visible during bypass, while the combined curve excludes it.

Double-click the graph background to create a bell in the first Off slot, resetting its type to Bell and Q to 1 and initializing frequency/gain before setting On. All 24 occupied slots prevent further creation. Alt/Option-click a node or press Space while it has focus to toggle bypass. Delete/Backspace or Alt/Option-right-double-click sets its slot Off, retaining settings and selecting the nearest remaining band. Click empty graph space to deselect. Tab between nodes to select overlapping bands; Off slots are reused through background double-click creation. Node positions reflect automation and preset recall without modifying saved values; frequencies above the effective DSP limit are displayed clamped. Nodes wait for a prepared sample rate. Lasso/group editing, solo, dynamic nodes, and configurable shortcuts remain future work.

The editor is continuously resizable from its bottom-right corner or through a supported host. Its default is **720 × 580** logical pixels. The band card grows with the square root of editor width relative to the 720-wide default: doubling width enlarges it about 1.41×. `ui/UiScale.h` applies slower growth to the header (0.7), bottom bar (0.4), and graph labels/nodes (0.6), using `1 + (cardScale - 1) * factor`. Fonts, icons and layout within each region share that region’s scale. Increasing only height adds graph space. Width ranges from 720 to 2160, with a width-dependent minimum height to keep the enlarged controls usable and a maximum height of 2400. The last dimensions persist when reopening the instance and in saved sessions. In very short windows, the card stays inside the graph and may overlap the selected node when no clear corner exists. Fullscreen and a separate fixed-control-size mode are not implemented.

The graph container spans the editor behind the header and footer. Plot insets keep curves, labels and nodes clear of their controls. The header contains branding and the Fill/Pre/Post switches over a fading background. The flat, edge-to-edge ash-grey footer contains directly accessible Input gain, Analyzer, and Output gain controls. Input and output sample-peak meters sit at the left and right edges of the graph. Analyzer settings open upward inside the editor. `HeaderBar` and `BottomBar` own their layouts; shared `UiLookAndFeel`, `IconButton`, `PanelDrawing` and `Palette` keep their presentation consistent with the floating panels. Analyzer controls are still created only on first use.

The graph updates when knobs or automation change, including with stopped playback or suspended audio processing. It needs a valid sample rate from `prepareToPlay`, but does not need a `processBlock` call. Before the host supplies a sample rate, it displays “Waiting for audio preparation”. The curve represents the settled EQ settings; audio smoothing, the wet/dry transition, and ringing are not visualized by this response curve. Automatic graph repaints target up to 30 Hz, independently of monitor refresh rate. When plot painting is expensive, automatic refresh slows to reserve time for controls and popup menus. Timing follows the visible plot even when opaque meters/footer clip the graph edges; very long paints still leave a pause for input after completion. Direct interaction repaints remain immediate. Graph work stops while the editor is hidden and resumes when it is shown. Headers and scale labels use small JUCE-buffered regions around the plot; grid lines draw directly above the spectrum. This avoids blending a full-size transparent artwork image every frame. Response curves, nodes and spectra remain dynamic.

The spectrum analyzer displays **Pre** (grey) and **Post** (purple) simultaneously behind the response curves. Each trace has an independent visibility switch; switching both off stops capture. Open **Analyzer** for quality, smoothing mode/amount and decay settings. Its selectors are embedded in the editor. **Fill** starts on; switch it off for outlines only. Fill is saved with the session independently of analyzer visibility and quality. **Normal** uses a 4096-point FFT at 44.1/48 kHz. **High** blends 16384/4096/1024-point FFTs for bass/mids/treble, with power-domain transitions at 200–400 Hz and 2–4 kHz. FFT sizes scale with sample rate. Quality affects analysis only, adding no audio latency.

Stereo analysis averages channel powers before conversion to dB: mono and identical dual mono have the same level; opposite-polarity channels do not cancel. The right-hand analyzer scale is independent of the left-hand EQ gain scale. Initial display defaults are −96 to 0 dBFS, a 4.5 dB/octave display tilt anchored at 1 kHz, ½ ERB power smoothing, and Medium exponential decay with immediate rises. Decay follows the analyzer dB range and elapsed analysis time independently of UI frame rate. This is a conditioned spectral display, not an integrated loudness meter or power-density measurement. The Hann normalization gives a coherent low-frequency peak sine a 0 dBFS reference before tilt/smoothing; smoothing, off-bin tones, and High's noise-power normalization affect displayed tone heights. High matches the expected broadband noise level across resolutions rather than guaranteeing identical narrow-tone peaks to Normal. Frequency smoothing offers ERB (¼, ½, 1 ERB) or Octave (1/24, 1/12, 1/6, 1/3 octave), remembering the amount for each mode. Decay offers Very Fast, Fast, Medium, Slow and Very Slow. Spectrum-bin decay history survives window resizing; suspended input releases toward silence after 250 ms without new samples. These are saved display preferences, not automatable EQ parameters.

Audio capture uses preallocated, bounded storage; FFTs and path building run on a separate editor-owned worker. Closing/hiding the editor stops capture and analysis. Sample gaps, sample-rate/layout changes and editor reopening reset affected history. Host suspension fades the old traces away after 250 ms without new audio; actual incoming silence naturally rolls through the FFT windows. Resizing rebuilds drawing paths without resetting FFT history. Pre/Post/quality preferences are saved in plugin state as display preferences, outside the automatable band parameter list. The post tap follows final output after the global warm-bypass mix.

## Input/output gain and peak meters

Input and output trims range from **−30 to +30 dB**, default 0 dB, with sample-rate-aware **20 ms linear-amplitude ramps**. Their IDs are `input.gain` and `output.gain`, appended after existing band parameters. Drag a footer value vertically; hold Shift when starting the drag for fine adjustment. Double-click or press Enter to type an exact value. Enter commits, Escape or focus loss cancels text entry, and Ctrl/Cmd-double-click resets to unity. Typed edits, wheel changes, resets and drags notify the host with complete gestures. If the UI stalls for more than 200 ms during a gain drag, accumulated mouse movement is discarded and the gesture ends; release and start a fresh drag. Holding the pointer still while the UI remains responsive does not cancel the drag. Gain does not change the band-only response curve.

Scroll over either footer gain value for **0.5 dB steps**, or **0.1 dB with Shift**. Smooth scrolling retains fractional movement. Wheel input is ignored during dragging, text editing and inertial scrolling; it updates gain immediately while spectrum and meters retain their shared refresh cadence. Pending local gain feedback can defer an automatic graph/meter update by one eligible VBlank so the readout gets a paint opportunity; continuous input cannot indefinitely defer animation. A paint already running still blocks input until it finishes.

Signal path: **Input → input trim → IN meter / Pre spectrum → EQ → output trim → OUT meter / Post spectrum → output**. Both meters work independently of Pre/Post visibility or analyzer quality. Peaks are measured during the gain loops and published once per audio block through single-producer atomic latches, without allocation, locks, queues or an application-level retry loop. Float atomics must be always lock-free on the build target. The UI is the sole consuming reader; readings are independent per-channel interval maxima, not a sample-aligned four-channel frame. They are not RMS or oversampled true peak measurements.

Each strip shows L/R (a single M bar for mono), a −60…+6 dBFS scale, immediate peak rises, 24 dB/s release, and a tick held for two seconds then falling at 3 dB/s. The numeric maximum holds until the strip is clicked or the editor/processing session restarts; values above 0 dBFS turn red. Readouts update at 10 Hz and bars at about 30 Hz, repainting only changed regions over narrow opaque cached artwork. No meter worker is introduced. Metering continues measuring while the editor is closed, but its transient readings are not saved. Initial editor polling discards old closed-editor peaks. Float headroom above 0 dBFS is retained; the indicator is not a limiter. Nonfinite samples or gain-stage float overflow are replaced with silence rather than sent onward.

## Development

Requires CMake 3.25+, Ninja, a C++23 compiler, and the JUCE platform development dependencies. CMake fetches pinned `zldsp_fft` and Highway analyzer dependencies through CPM. For Linux debugging, install GDB and the VS Code Microsoft C/C++ extension; CMake Tools is also recommended.

```bash
git submodule update --init --recursive
cmake -S . -B Builds -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DJUCE_BUILD_EXTRAS=ON
cmake --build Builds --config Debug --target OpenQ_VST3 OpenQ_Standalone AudioPluginHost --parallel 2
cmake --build Builds --target Tests Benchmarks --parallel 2
ctest --test-dir Builds --verbose --output-on-failure
```

Slot capacity is the compile-time `bandCount` in `source/BandParameters.h`. Multiband tests derive parameter counts, final-slot indices, and response totals from it, and keep per-slot fixtures inside the parameter ranges.

Shared band limits and defaults live in `source/dsp/BandLimits.h`; graph scales and coordinate conversions live in `source/ui/ResponseMapping.h`; shared UI colors live in `source/ui/Palette.h`. Parameter smoothing and wet/dry fade durations are named locally in `BandFilter.cpp`. Changing these values changes product behavior and should be validated separately from refactoring.

The card uses SVG icons embedded as JUCE BinaryData and recolored in C++. To normalize multiline icons with the imported ZL helper, run `python3 ../../tools/format_svg_icons.py` from `assets/icons/`. It processes SVGs in the current directory only; it is not a general XML formatter.

VS Code **Run Build Task** offers `Build plugin binaries (Debug)` and `Build plugin binaries (Release)`. **F5** uses `VST3: JUCE AudioPluginHost (Linux)`, builds the VST3 and host, then launches the host under GDB. In AudioPluginHost, scan/load `Builds/OpenQ_artefacts/Debug/VST3/Open-Q.vst3`; breakpoints become active when the plugin loads.

Release builds use `Builds/Release`, keeping Debug available for development. Use Release when making music or measuring CPU usage. Builds stay in the project directory rather than installing plugins automatically.

GitHub Actions builds and tests on Linux, macOS, and Windows and runs pluginval. Signing and notarization are deferred; artifacts are unsigned (ZIP on Linux/macOS, installer on Windows). Intel IPP is disabled initially; revisit it when profiling identifies a useful optimization. The three-platform matrix consumes CI minutes on private repositories; reduce the matrix during active development if needed.

State schema 7 stores all 147 parameters and the pinned bell (`zle-ivantsov-v1`) shelf (`zle-ivantsov-shelf-v1`) and cut (`zle-ivantsov-cut-v1`) design revisions. Parameter IDs use `band.0.frequency`, `band.0.gain`, `band.0.q`, `band.0.status`, `band.0.type`, and `band.0.slope` through index 23. Earlier development sessions/presets (schema 6 and below) are unsupported; no migration is provided for this unreleased plugin; eight-slot development states are also rejected because the saved bank count must match. Existing parameter IDs retain their ordering; rescan the plugin in your host if it caches the earlier parameter list. Status values are Off=0, Bypass=1, On=2; saved status values must be integral and in range. Type values are Bell=0, Low Shelf=1, High Shelf=2, Low Cut=3, High Cut=4. Slope choice indices map to the eight ordered labels above; slope is retained but inactive for bells/shelves. Both choices must be integral and in range. Additional responses remain future work; the coefficient-design function is separate from the channel-state processor. DSP uses ordinary floating-point semantics in optimized builds so finite-value checks remain effective.

Gain responsiveness diagnostics: focus the plugin and press **Ctrl+Shift+T** to start a bounded in-memory timing capture; press it again to stop and export `Open-Q-gain-timing*.csv` to the system temporary directory (the console reports the path). Compare wheel and drag in separate short captures with Fill on/off. Capture is off by default, shared across editors in the loaded plugin module, and measures callbacks and paint completion rather than screen presentation. See `yohan-docs/gain-input-timing-test.md` for the manual protocol and CSV fields.

Total Bypass is the rightmost header icon; its accent is lit when bypassed. It fades over 20 ms to raw plugin input, bypassing EQ and both trims audibly while keeping the wet engine and trim smoothers running. Band settings and target curves remain editable. Post analysis and OUT metering follow final mixed output; Pre and IN remain after input trim, so Pre/Post need not match in bypass when input trim is nonzero. The `global.bypass` parameter is automatable, saved and designated as host bypass. A host that suspends processing cannot keep the engine warm. Gain matching and EQ-only bypass are not included.

During Total Bypass, response curves, nodes, spectrum traces/fills and meter bars/hold ticks use dimmed colours. Grid lines, axis labels, meter scales/readouts, cards and controls retain normal brightness. This is presentation only: editing and analysis continue. Appearance changes share the existing admitted graph/meter frames, with no dimming overlay or animation timer.

The header **Presets** button opens the ZLE-derived embedded browser. Groups appear on the left; single-click selects a preset and double-click loads it. Search matches preset/group names. Enter in **New Group** creates a group; Enter in **New Preset Name** saves the current sound, asking before replacing an existing file. Trash buttons ask before deleting a preset or group. Close with X or click outside. Closing clears the search while retaining the selected group. The folder arrow reveals the library under JUCE's user application-data directory → `Yohan Senanayake/Open-Q/Presets`.

Presets use Open-Q-specific JSON and store bands and input/output trims. Loading preserves the current Total Bypass, analyzer options and editor size. ZLE preset files are not directly compatible. Library scanning and file operations are intentionally synchronous for this first port; opening a very large or slow library can pause the UI. Search uses cached entries. There is no new animation timer, native browser window or full-editor image cache. The header entry is currently labelled Presets; persistent loaded-name/dirty tracking and previous/next audition are deferred.
