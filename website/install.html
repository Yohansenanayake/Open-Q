Install Open-Q

Start with Choose your download below, then follow the installation steps for your operating system. Preview builds are for testing: save your work and keep the previous installer for rollback.

Downloads are currently unsigned/not notarized and may show operating-system warnings. Download from our GitHub Releases and compare the file's SHA-256 hash with that release's SHA256SUMS.txt. On macOS/Linux use shasum -a 256 filename or sha256sum filename; on Windows use PowerShell Get-FileHash filename -Algorithm SHA256.

Choose your download

Open-Q needs a 64-bit DAW. Match the plugin to the DAW you run, using these steps:

  • Windows: open Settings → System → About and read System type. For an x64-based processor (Intel/AMD), choose Windows x86-64, or use the optional AVX2 check below. For an ARM-based processor, choose Windows ARM64 with a native ARM64 DAW; choose standard Windows x86-64 if you installed the x64 version of your DAW.
  • Mac: open Apple menu → About This Mac. If Chip says Apple M1, M2 or another Apple chip, choose Apple silicon. If Processor says Intel, choose Intel Mac. On Apple silicon, a DAW running through Rosetta needs the Intel Mac build instead. In Finder, select the DAW in Applications and choose File → Get Info: if Kind says Application (Intel), or Open using Rosetta is enabled for a Universal app, use Intel plugins. See Apple’s Rosetta guide.
  • Linux: open a terminal and run uname -m. For x86_64, choose Linux x86-64, or use the AVX2 check below. For aarch64 or arm64, choose Linux ARM64 with a native ARM64 DAW. Other architectures have no matching build.

Should I choose AVX2?

On Intel/AMD Windows and Linux systems, the standard x86-64 build is the simplest choice: it needs no AVX2 check. Both builds have the same EQ features and filter designs. The optional x86-64 AVX2 build may reduce CPU usage on compatible systems. There is no separate AVX2 download for Mac or ARM64.

The i3/i5/i7 name alone does not establish compatibility. To choose AVX2, run the check for your operating system below. It checks the extra requirements too, rather than AVX2 alone.

Windows: check whether to choose AVX2
  1. For an Intel/AMD x64-based PC, download Coreinfo from Microsoft and extract its ZIP.
  2. Open the extracted folder in File Explorer. Click the address bar, type powershell, and press Enter.
  3. Paste the whole block below and press Enter. Accept Microsoft’s licence if prompted. This checks your CPU features.
$required = 'AVX AVX2 BMI1 BMI2 F16C FMA LZCNT MOVBE XSAVE OSXSAVE AES PCLMULDQ CX16 LAHF-SAHF POPCNT SSE3 SSSE3 SSE4.1 SSE4.2'.Split(' ')
$report = & .\Coreinfo64.exe -f 2>&1 | Out-String
$passed = $LASTEXITCODE -eq 0
foreach ($feature in $required) {
    $pattern = '(?m)^[ \t]*' + [regex]::Escape($feature) + '[ \t]+\*'
    if ($report -notmatch $pattern) { $passed = $false }
}
if ($passed) { 'Choose Windows x86-64 AVX2' } else { 'Choose Windows x86-64' }

Follow the printed choice: Choose Windows x86-64 AVX2 means select that download under More builds. Choose Windows x86-64 means select the standard Windows download. If Coreinfo cannot run or no choice appears, use standard x86-64.

Linux: check whether to choose AVX2

After confirming uname -m prints x86_64, paste the whole block into your terminal. It reads the CPU features reported by your kernel and checks every listed processor.

awk '
BEGIN {
    n = split("avx avx2 bmi1 bmi2 f16c fma abm movbe xsave aes pclmulqdq cx16 lahf_lm popcnt pni ssse3 sse4_1 sse4_2", required)
    ok = 1
}
/^flags[[:space:]]*:/ {
    seen = 1
    for (i = 1; i <= n; i++)
        if ($0 !~ ("(^|[[:space:]])" required[i] "([[:space:]]|$)")) ok = 0
}
END { print ((seen && ok) ? "Choose Linux x86-64 AVX2" : "Choose Linux x86-64") }
' /proc/cpuinfo

Follow the printed choice: Choose Linux x86-64 AVX2 means select that download under More builds. Choose Linux x86-64 means select the standard Linux download. If the command cannot run or no choice appears, use standard x86-64.

This is a conservative check: missing kernel information also selects the standard build. In a virtual machine, run it inside the same virtual machine as your DAW.

These checks cover the x86-64-v3 instruction set plus AES and carry-less multiplication, as required by Open-Q’s AVX2 build. The Linux check uses kernel-reported CPU flags. Keep the standard build if compatibility cannot be confirmed.

Windows installation

Run the versioned .exe installer. Select VST3, CLAP and/or Standalone, then follow setup. Plugins go into their standard Common Files folders; the standalone app gets a Start-menu shortcut. Use Windows Installed Apps to uninstall.

macOS installation

Extract the ZIP. Copy the desired bundles to these folders, creating them if needed:

  • VST3: ~/Library/Audio/Plug-Ins/VST3/
  • AU (.component): ~/Library/Audio/Plug-Ins/Components/
  • CLAP: ~/Library/Audio/Plug-Ins/CLAP/
  • Standalone (.app): ~/Applications/ or /Applications/

Finder's Go → Go to Folder accepts these paths. If macOS blocks opening trusted downloaded software, follow Apple's Privacy & Security instructions. There is no macOS installer yet. Delete the copied bundles to uninstall.

Linux installation

Extract the ZIP. Copy the VST3 bundle into ~/.vst3/ and the CLAP plugin into ~/.clap/, or use the plugin directories configured in your DAW. Launch the executable in the Standalone directory. If extraction removed its executable permission, run chmod +x Standalone/Open-Q. Delete copied files to uninstall.

After installing

Restart your DAW or rescan plugins. Uninstalling binaries does not delete your saved user presets. To roll back, close your DAW and reinstall the previous version. This project is still in development; saved-session compatibility across early versions is not guaranteed.

Report a problem with the full download version, OS, CPU architecture and DAW version.
